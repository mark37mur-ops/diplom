# Черновик: синтетические эксперименты

Многоиндексная модель панельных данных с латентными факторами в ошибке:

$$Y_{it} = c_i + X_{it}^\top P^\top \ell_i + \gamma_i^\top f_t + \varepsilon_{it}.$$

Наклоны индивидов $b_i = P^\top \ell_i$ лежат в общем $m$-мерном подпространстве, а в ошибке есть $r$ латентных факторов $f_t$, которые могут быть связаны с признаками.

## Что здесь лежит

- `latentnye_faktory_sintetika.ipynb` — ноутбук с экспериментами, уже выполненный: все таблицы и графики сохранены внутри. Код алгоритма находится прямо в ноутбуке, отдельные файлы для запуска не нужны.
- `panelfac.py` — те же функции отдельным модулем: генерация данных, оценка, метрики.
- `realnye_dannye_orangejuice.ipynb` — проверка на реальных данных: недельные продажи апельсинового сока в 83 магазинах сети Dominick's (11 марок). Ноутбук уже выполнен; алгоритм в нём доработан для панели с пропусками.
- `myagkiy_malyi_rang.ipynb` — мягкий малый ранг: наклоны лежат около подпространства индексов, а не строго в нём (см. ниже). Проверка теоремы, синтетика и данные Dominick's. Ноутбук уже выполнен.
- `panelmiss.py` — функции для панели с пропусками (те же, что в ноутбуке с реальными данными), `panelsoft.py` — мягкий малый ранг.
- `pwt_sravnenie.ipynb` — сравнение с Zhang и Xia (2026, [SSRN 7029038](https://ssrn.com/abstract=7029038), код: [zmk-98/RRPM-IFEs](https://github.com/zmk-98/RRPM-IFEs)) на их данных Penn World Table: воспроизведение их результата, сходимость их алгоритма и нашего, прогноз. Нужны `zxmodel.py` и `zx_rpc_pwt.R` (запускает их код из склонированного репозитория, сам код не копируется).
- `energopotreblenie_zdaniy.ipynb` — энергопотребление 758 зданий (Building Data Genome Project 2): жёсткий и мягкий малый ранг, факторы, разная длина обучения.
- `panelfast.py` — быстрая (векторизованная) версия алгоритма для панели с пропусками; результаты совпадают с `panelmiss.py`.

## Эксперименты

1. Один набор данных: сравнение с МНК по каждому индивиду, многоиндексной оценкой без факторов и «оракулами», которым известны истинные факторы.
2. Сходимость алгоритма.
3. Выбор числа факторов $r$ и числа индексов $m$ по сингулярным числам.
4. Зависимость ошибки от длины рядов $T$ (Монте-Карло).
5. Наблюдений на индивида меньше, чем признаков ($T < d$).
6. Неверно выбранное число факторов.
7. Сила связи признаков с факторами.
8. Скорость: шаг через проекцию против чередования по остаткам.

## Мягкий малый ранг

Наклоны $b_i = P^\top \ell_i + \delta_i$, где $\delta_i$ — небольшое собственное отклонение индивида, ортогональное индексам. Отклонения штрафуются с весом $\kappa$:

$$\hat b_i(\kappa) = (\hat G_i^F + \kappa \Pi)^{-1} Z_i^F, \qquad \Pi = I - P^\top P.$$

При $\kappa = 0$ это МНК по каждому индивиду, при $\kappa = \infty$ — жёсткий малый ранг. Теорема: малое $\kappa > 0$ всегда лучше МНК, а при случайных отклонениях с дисперсией $\tau^2$ значение $\kappa_0 = \sigma^2/\tau^2$ даёт оценку строго лучше обеих крайних. $\kappa$ подбирается эмпирическим Байесом по всей панели.

## Penn World Table и Zhang–Xia

Их результат (2 индекса, 1 фактор, нагрузки, $R^2$) воспроизводится точно. Их алгоритм (чередование по остаткам) останавливается раньше минимума суммы квадратов: 9.1420 за 570 итераций. Наш проекционный алгоритм приходит к 9.1379 за 198 итераций, и из их точки остановки сумма квадратов уменьшается уже на первой итерации. По прогнозу в этой макропанели разнородность наклонов не помогает: лучше всех общие наклоны с одним фактором.

## Как запустить

Нужны Python 3, `numpy`, `pandas`, `matplotlib` и Jupyter. Ноутбук с синтетикой пересчитывается примерно за 3–4 минуты. Ноутбуку с мягким малым рангом нужны модули `panelfac.py`, `panelmiss.py`, `panelsoft.py` в той же папке, ноутбукам с PWT и зданиями — `panelfast.py` (и для PWT `panelfac.py`, `zxmodel.py`, `zx_rpc_pwt.R`, R и склонированный репозиторий авторов в папке `RRPM-IFEs`). Данные PWT: `pwt1001.csv` (сайт GGDC или R-пакет `pwt10`); данные зданий: три файла BDG2 в папке `raw/` (см. ноутбук).

## Реальные данные

Данные взяты из R-пакета [`bayesm`](https://CRAN.R-project.org/package=bayesm) (датасет `orangeJuice`, источник: A. L. Montgomery, *Marketing Science*, 1997; исходная база Dominick's — James M. Kilts Center for Marketing, University of Chicago Booth School of Business). Сами данные в репозиторий не выложены. Чтобы пересчитать ноутбук, выполните в R

```r
library(bayesm); data(orangeJuice)
write.csv(orangeJuice$yx, "orangejuice_yx.csv", row.names = FALSE)
```

и положите `orangejuice_yx.csv` рядом с ноутбуком. Пересчёт каждого из двух ноутбуков с реальными данными занимает около 15–20 минут.
